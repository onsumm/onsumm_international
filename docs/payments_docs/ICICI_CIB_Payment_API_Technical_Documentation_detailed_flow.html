CIB Payment API

Adhoc payment & collection integration for Corporate Internet Banking (CIBNEXT). Covers registration, balance, payments across NEFT / RTGS / IMPS / FT / Virtual Accounts, status inquiry, NEFT incremental tracking, and statements — with flows, payloads, and the full error catalog.

Bank: ICICI Bank Ltd.
Platform: CIBNEXT
Model: Partner / Aggregator
Auth: IP whitelist + 4096-bit PKI
Currency: INR only
Payment: Without OTP (bypassable)

00 Overview

The CIB Payment API lets a registered Partner / Aggregator initiate and track payments on behalf of their corporate clients through ICICI Bank's CIBNEXT platform. It is an adhoc payment API (no beneficiary pre-registration by default) supporting NEFT, RTGS, IMPS, ICICI-to-ICICI FT, and Virtual Account collections. All traffic is secured by IP whitelisting and public-key encryption of responses.

01 System Architecture

Requests originate from the Partner's whitelisted server, traverse ICICI's API gateway, and are processed by the CIB engine against Core Banking (CBS) and the payment rails (RBI for NEFT/RTGS, NPCI for IMPS). Responses are encrypted with the Partner's public key before return.

Encryption boundary at ICICI Whitelist enforced at gateway

02 Transaction Lifecycle

Every payment follows onboarding → initiation → workflow (optional) → rail processing → status inquiry. The decision logic below drives whether a client should re-inquire, re-initiate, or stop.

Gateway errorWhere the STATUS tag is absent (API gateway error), always re-initiate the inquiry service — never the payment.

04 Data Model — Entity Relationships

The URN is the linkage key established at registration and reused across every service. Reconciliation keys are UNIQUEID (client) and UTRNUMBER (bank).

Cut-off behaviour • RTGS is not processed on Sundays & bank holidays; if the bene bank has a holiday, credit happens next business day.

19 Integration Notes & Constraints ↑ top

Access & eligibility • Only ICICI Current account holders with CIB transaction access can use this API — view/fraud-scheme access cannot.
• One-time registration requires CIB transaction access with one-time authorization in CIB.
• No registration on inactive/dormant CIB IDs; deleting the CIB user expires the registration.
• User needs Adhoc payment access (PMT) — else request it at a branch or via API SM/RM.
Workflow & charges • Authorization flow mirrors CIB; single-user CIB customers get STP once initiated.
• Maker-checker workflow and OTP are both bypassable on authorized confirmation.
• No registration charges; transaction charges per SOC; no additional API charges.
• Payment Txn ID reflects in the customer's bank statement for reconciliation.
Operational • Only INR domestic transfers — no FX via CIB.
• This is an adhoc payment API (no bene registration by default); confirm registered-bene requirement at integration start.
• On failure of an already-debited txn, manual credit-back occurs but CIB continues showing success.
• Some special-account clients may need a written request to enable registration.
• Support: corporatecare@icicibank.com · Customer Care via icicibank.com.

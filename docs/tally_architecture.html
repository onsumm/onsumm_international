Bi-directional. Polls int_connections every 60s. Runs PULL then PUSH for each due connection. Circuit breaker: 3 failures → ERROR.

tally_read.py PULL only
PULL steps (both workers)
1. fetch_ledgers() → XML
2. parse_ledgers() → dicts
3. Upsert dim_ledger_accounts
4. Upsert dim_end_customers
5. fetch_vouchers() → XML
6. parse_vouchers() → dicts
7. Upsert stg_invoices/bills/payments
PUSH steps (TallySyncWorker only)
1. Bridge fact_invoices.tally_push_pending
2. Push customer ledger masters
3. build_sales_voucher() → XML
4. import_xml() → Tally
5. Push receipt vouchers
6. Update sync_status = SYNCED

Integration / Connection
int_connections
Connection state, api_key_hash, pairing_token, last_sync_at, consecutive_failures, agent_version
int_sync_log
Job-level sync history: records_fetched, inserted, updated, errored, status
int_conflict_log
Conflicts when Tally import rejects a voucher
Raw Storage
raw_api_payloads
Full XML blobs stored as JSONB. Entity type: LEDGER or INVOICE
Dimension Tables
dim_ledger_accounts
Chart of accounts from Tally. account_type: ASSET/LIABILITY/INCOME/EXPENSE/EQUITY
dim_end_customers
Sundry Debtors from Tally ledgers. gstin, email, phone, billing_address_jsonb
dim_suppliers
Sundry Creditors from Tally ledgers. gstn, payment_terms_days, status
Staging Tables
stg_invoices + line_items
SALES vouchers. sync_status: PENDING → SYNCED. source=TALLY skipped on push.
stg_bills + line_items
PURCHASE vouchers. gstin_seller, supplier_id, outstanding_amount
stg_payments
RECEIPT/PAYMENT vouchers. amount, transaction_ref, is_reconciled
Fact Tables
fact_invoices
Promoted from stg. tally_push_pending flag triggers PUSH back to Tally.

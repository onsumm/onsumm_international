# Release v1.1.0 — Nova Reconciliation Service on app-dev

**Date:** 2026-08-26
**Branch:** `uat2` → `origin/uat2 @ 5fd6426`
**Target:** dev only (`~/app-dev`, `https://api.onsumm.ai/dev`). Prod (`~/app`, branch
`subhash`) is untouched by everything in this document.

**Scope of this deploy:** the API side of `uat2` is already live on app-dev. The one thing
still missing is the **Nova Reconciliation Service** — a second long-running process with its
own port, systemd unit, and nginx location. That's all §4 does.

**No database migration is performed.** The `nova_reconciliation_*` tables were applied
directly to the shared platform DB when the service was built (see
`services/nova_reconciliation/README.md`), so they already exist. §4.2 is a **read-only**
preflight that confirms this and stops if anything is missing — it never issues DDL.

## 4. Deploying the Nova service to app-dev

§4.1–§4.6 are one-time. After that, every push is §4.8.

```bash
ssh -i ~/Downloads/onsumm-mumbai.pem ec2-user@13.232.207.113
cd ~/app-dev
```

### 4.1 Pull the code

```bash
git fetch origin uat2
git checkout uat2
git pull origin uat2
git log -1 --oneline          # expect 5fd6426 or later
ls services/nova_reconciliation/app/main.py    # the service must be present
```

### 4.2 Preflight — confirm the schema is already there (read-only)

No DDL. This only checks that what the service expects already exists. If any of these fail,
**stop and report it** rather than creating anything — the tables belong to a shared database.

```bash
DBURL=$(grep -m1 '^DB_URL=' ~/app-dev/.env | cut -d= -f2-)

# The four tables the service owns — all four must be listed.
psql "$DBURL" -c "\dt nova_reconciliation_*"

# The credentials table must have a `brand` column (see §6.2).
psql "$DBURL" -c "SELECT column_name FROM information_schema.columns
                   WHERE table_name = 'int_nova_credentials' ORDER BY 1"
```

Expected: `nova_reconciliation_module_aliases`, `nova_reconciliation_runs`,
`nova_reconciliation_lines`, `nova_reconciliation_bill_queue`, and an `int_nova_credentials`
that includes `brand`.

### 4.3 Install dependencies

The service adds `httpx` and `cryptography` on top of what the API already has.

```bash
python3.11 -m pip install --user -r services/nova_reconciliation/requirements.txt
```

### 4.4 Add the env vars

Append to `/home/ec2-user/app-dev/.env` (shared by both units):

```env
# --- Nova Reconciliation Service ---
NOVA_RECONCILIATION_PORT=8102
NOVA_RECONCILIATION_CORS_ORIGINS=https://<your-dev-amplify-domain>
NOVA_BILLING_BASE_URL=https://api.lendix.ai

# Start with the orchestrator OFF — read §6.1 before flipping this.
NOVA_ORCHESTRATOR_ENABLED=false
NOVA_ORCHESTRATOR_POLL_SECONDS=120
NOVA_ORCHESTRATOR_MIN_INVOICE_DATE=2026-08-01

# The dev API proxies /api/billing/bill/{id}/reconcile to the service.
NOVA_RECONCILIATION_URL=http://127.0.0.1:8102
```

`NOVA_KEY_ENCRYPTION_KEY` is already in that file — leave it exactly as is. The API encrypts
tenant Nova keys with it and the service decrypts them; they must stay identical, which holds
automatically while both read this one file.

`NOVA_RECONCILIATION_DB_URL` is deliberately omitted — the service falls back to `DB_URL`, the
same database the dev API already uses.

Set `NOVA_RECONCILIATION_CORS_ORIGINS` to the real dev frontend origin. It defaults to `*`,
which is wrong for anything past localhost.

### 4.5 Install the systemd unit

```bash
sudo cp ~/app-dev/services/nova_reconciliation/deploy/onsumm-nova-dev.service \
        /etc/systemd/system/onsumm-nova-dev.service
sudo systemctl daemon-reload
sudo systemctl enable --now onsumm-nova-dev

systemctl is-active onsumm-nova-dev              # -> active
curl -s http://127.0.0.1:8102/health             # -> {"status":"ok"}
sudo journalctl -u onsumm-nova-dev -n 50 --no-pager
```

If it fails to start, the journal will almost always show either a missing Python package
(§4.3) or a DB connection error (the service builds its own pool from `DB_URL` at first use).

### 4.6 Add the nginx location

Back up first, then add a third location to the `api.onsumm.ai` :443 server block in
`/etc/nginx/conf.d/onsumm-api.conf`, **above** `location /`:

```nginx
location /dev-nova/ {
    proxy_pass http://127.0.0.1:8102/;   # trailing slash strips the /dev-nova prefix
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_read_timeout 300;
    proxy_send_timeout 300;
}
```

```bash
sudo cp /etc/nginx/conf.d/onsumm-api.conf /etc/nginx/conf.d/onsumm-api.conf.bak.$(date +%s)
sudo nano /etc/nginx/conf.d/onsumm-api.conf
sudo nginx -t && sudo systemctl reload nginx
curl -s https://api.onsumm.ai/dev-nova/health    # -> {"status":"ok"}
```

Then restart the dev API so it picks up `NOVA_RECONCILIATION_URL`:

```bash
sudo systemctl restart onsumm-api-dev
```

### 4.7 Frontend (Amplify, branch `uat2`)

Add one environment variable alongside the existing `VITE_API_URL`, then redeploy the branch:

| Variable | Value |
|---|---|
| `VITE_API_URL` | `https://api.onsumm.ai/dev` (unchanged) |
| `VITE_NOVA_RECONCILIATION_API_URL` | `https://api.onsumm.ai/dev-nova` |

`frontend/src/api/novaReconciliation.ts` defaults to `http://localhost:8100` when that var is
missing — on a deployed HTTPS site the browser blocks that as mixed content, so the Nova page
renders empty instead of erroring visibly. Blank Nova panels after deploy? Check this first.

### 4.8 Every subsequent deploy

```bash
bash ~/app-dev/services/nova_reconciliation/deploy/deploy-dev.sh
```

Pulls `uat2`, installs both requirements files, restarts both units, prints health for each.
No DDL, ever.

## 6. Risks and gotchas

### 6.1 The orchestrator will reconcile production bills and spend real Nova API calls

Dev runs against the **prod RDS** (`docs/DEV_ENVIRONMENT.md` §6). On its first sweep the
orchestrator discovers *every* `fact_invoices` row belonging to a Nova-mapped vendor — the
entire historical backlog — queues it, and makes a live billing API call per bill per brand.
That's real third-party usage against real tenants' keys, initiated from a dev box. It also
**writes** rows to `nova_reconciliation_*` in the shared database.

Hence `NOVA_ORCHESTRATOR_ENABLED=false` and `NOVA_ORCHESTRATOR_MIN_INVOICE_DATE=2026-08-01`
in §4.4. Recommended sequence:

1. Deploy with the flag off. Only the background *loop* is gated by it; the date floor applies
   either way.
2. Trigger exactly one sweep by hand and read what it did:
   ```bash
   curl -s -X POST https://api.onsumm.ai/dev-nova/v1/orchestrator/run-once | python3 -m json.tool
   curl -s https://api.onsumm.ai/dev-nova/v1/orchestrator/status | python3 -m json.tool
   ```
   `run-once` runs the same discover+process sweep synchronously — blast radius is one sweep
   you're watching, not one every 120 seconds.
3. Once the queue looks right — sane counts, `SKIPPED`/`ERROR` rows with reasons you
   understand — set `ENABLED=true` with the date floor still in place, restart, and watch
   `journalctl -u onsumm-nova-dev -f` through two automatic sweeps before widening the floor.

### 6.2 `backend_ocr/app/sql/nova_credentials.sql` is stale — do not run it

That file creates `int_nova_credentials` with `tenant_id` as PRIMARY KEY and no `brand`
column. `nova_credentials_api.py` has since moved to one key *per brand* and issues
`ON CONFLICT (tenant_id, brand) WHERE brand IS NOT NULL` / `ON CONFLICT (tenant_id) WHERE
brand IS NULL`, both of which need partial unique indexes the old shape doesn't have — saving
a key would fail outright.

The §4.2 preflight checks for the `brand` column. If it's missing, the live table is the old
shape and saving a Nova key will error. That needs a schema decision, not a quiet fix during
a deploy — surface it and stop. The corrected DDL is documented in
`docs/NOVA_RECONCILIATION_LOGIC.md` §9.1; the stale `.sql` file should be deleted in a
follow-up so nobody runs it.

### 6.3 The Nova service has no authentication

`services/nova_reconciliation/app/routes.py` has no auth dependency anywhere. The frontend
sends a `Bearer` token; the service ignores it. `tenant_id` arrives as a plain query
parameter, so anyone who can reach the origin can read any tenant's reconciliation data by
guessing a UUID.

Exposing it at `https://api.onsumm.ai/dev-nova/` is therefore acceptable **only** as a
time-boxed UAT arrangement. Mitigations, cheapest first:

- Restrict `location /dev-nova/` by source IP (`allow`/`deny`) to office/test IPs for the UAT
  window.
- Set `NOVA_RECONCILIATION_CORS_ORIGINS` to the exact dev frontend origin (browser-level only;
  it does not stop a direct `curl`).
- Proper fix before any prod exposure: verify the platform JWT in the service and derive
  `tenant_id` from the token instead of the query string, as `backend_ocr/app/auth.py` already
  does for the main API.

Do not carry this nginx location into prod as-is.

### 6.4 Smaller things

- **The systemd unit deliberately has no `EnvironmentFile=`.** `app/config.py` already
  `load_dotenv()`s `~/app-dev/.env` from three directories up, and systemd's env parser is
  stricter about quoting than dotenv's — pointing both at the same file only adds a way for
  the unit to fail to start.
- **`lendix/nova_vendor_mapping.json` is hot-reloaded** on file mtime, so finance can edit
  rates without a restart. It also ships in the repo, which means a `git pull` can change
  reconciliation behaviour with no restart and no log line announcing it.
- **`.env` lists `NOVA_KEY_ENCRYPTION_KEY` twice** with the same value. Harmless (last wins),
  worth tidying — if the two ever diverge, key decryption breaks silently.
- **`docs/aws-deploy/` is stale** — it documents `ubuntu@` / `/home/ubuntu/app` / branch
  `subhash`. The authoritative dev topology is `docs/DEV_ENVIRONMENT.md` plus this document.

## 7. Rollback

Nova only — leaves the dev API running:

```bash
sudo systemctl disable --now onsumm-nova-dev
sudo cp /etc/nginx/conf.d/onsumm-api.conf.bak.<ts> /etc/nginx/conf.d/onsumm-api.conf
sudo nginx -t && sudo systemctl reload nginx
```

Nothing to undo in the database — this deploy issues no DDL. If the orchestrator ran and you
want its output gone, delete from `nova_reconciliation_bill_queue` / `_runs` / `_lines`
(cascades from `_runs`) for the affected tenants; no other table is written.

Prod (`onsumm-api`, port 8001, `location /`) is unaffected by every command in this document.
